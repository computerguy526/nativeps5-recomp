# Guest memory model: adversarial test suite

Branch `m1-memtests`. Tests written from `docs/m1/memory.md`, SPEC 3.6/3.10/4.2 and `docs/m0/S1.md`, to find where the code diverges from the intended behaviour. No implementation code was changed in that branch.

**Status (round 2, `memory-fixes-2.md`): every defect below is fixed and every case passes under `tools/memtests.sh --strict` (240 cases; the KNOWN-FAIL machinery is kept for future use, nothing is deferred in this suite). The list is kept as the record of what the suite found.**

## Running

`tools/memtests.sh [--no-guest] [--strict] [--short] [--no-doc]` runs everything and regenerates this file (the table below is generated by `tools/memtests_report.py`; the text above "Results" is `docs/m1/memtests_findings.md`).

| Layer | Where | How it runs |
|---|---|---|
| Go (`-race`) | `pkg/guestmem`, `pkg/elfloader`, `pkg/thunkgen` `*memtests_adv_test.go` | layout, mode scan/selection, manifest, sparse image, loader malformations, relocations vs bias, descriptor validation, thunk classifier gaps |
| Thunk execution | `pkg/thunkgen/memtests_adv_test.go` + `tests/memtests/thunk_driver.c` | generated thunks compiled against a fake register file, both modes |
| C host harnesses | `pkg/runtime/memtests_darwin_test.go` runs `tests/memtests/{arena,vm,xlate,conc}_adv.c` | arena/reservation (incl. Metal), VM extent manager and syscalls through the real `shim_*` entry points, pointer translation, concurrency, identity-mode thunk asm |
| PS5 guest programs | `tests/ps5/memtests/*.c`, `tools/memtests_guest.sh` | payload SDK build, base and identity translation, run only via `tools/run_sandboxed.sh`; fault cases check the crash report's classification |

## KNOWN-FAIL policy

A case whose expectation the current implementation violates is recorded with a reason and reported as **KNOWN-FAIL** (Go: `t.Skip("KNOWN-FAIL: ...")` raised only after the violation was observed; C and guest programs: `MT_KNOWN` / `known=` in `cases.list`). The case becomes PASS by itself once the bug is fixed. `MEMTESTS_STRICT=1` (or `tools/memtests.sh --strict`) turns every KNOWN-FAIL into a failure: that is the fix loop's worklist. No build tags are used.

## Defects found (fix-loop input)

See the KNOWN-FAIL rows below; the root causes are:

1. **Fixed map at address 0** is treated as "no address" and mapped elsewhere (`recomp_vm_map`: `addr != 0 && MAP_FIXED`). ADR: a fixed request that cannot be honoured fails.
2. **`sceKernelMapFlexibleMemory` / `ReserveVirtualRange` / `MapDirectMemory` with MAP_FIXED round the length to 64 KiB** and replace the neighbouring 16 KiB pages (ADR: fixed lengths round to pages so a neighbour cannot be clobbered).
3. **`sceKernelMapDirectMemory(MAP_FIXED)` over an existing mapping deadlocks** (`g_direct_mutex` held across `recomp_vm_map` -> `recomp_vm_free` -> `ps4_direct_mem_on_unmap`).
4. **`recomp_vm_free` length wrap**: `munmap(addr+0x200, 2^64-0x100)` unmaps one page and returns 0.
5. **Concurrent overlapping munmap/MAP_FIXED lose mappings**: two `recomp_vm_free` calls collect the same extents and the slower one marks a newly created mapping free (list says free, host pages still RW).
6. **Crash snapshot (`nps5_mem_classify`)**: seqlock reader lacks an acquire fence (torn entries observed); `nps5_mem_release` keeps stale image/mapping tables; `nps5_mem_note_range` silently drops ranges beyond 64; snapshot beyond 2048 entries is reported as UNMAPPED; adjacent `thread_stack` mappings are merged so the second stack's guard page is not classified as a guard.
7. **Arena**: base-mode slot search stops after 16 slots (ADR: up to 2^47); `nps5_mem_commit/decommit/protect_inner` accept a wrapping length as an empty no-op success.
8. **Pointer translation**: `NPS5_G2H` of an out-of-range guest pointer yields a host address outside the reservation silently (no check, no abort).
9. **Guest protections not enforced** (known, ADR "Protection"); `sceKernelMprotect` also retags the whole extent instead of splitting, returns 0 for unmapped ranges and wrapping lengths, and for ranges past `guest_hi`.
10. **`sceKernelAllocateDirectMemory`** accepts length 2^64-1 (rounds to 0) and non-power-of-two alignments; **`ReleaseDirectMemory`** leaves the guest mappings of the released memory accessible.
11. **`recomp_create_thread_context`**: a huge stack size rounds to 0 and yields a thread with no stack.
12. **`shim_writev` (base mode)** dereferences an unmapped guest iovec array in the thunk (host crash instead of EFAULT).
13. **Stack overflow (main and thread) hangs** instead of producing a classified crash report (SPEC 3.10).
14. **Guest code is writable** from the guest (stores into the RX segment do not fault), contrary to "guest code is read-only".
15. **Loader**: overlapping PT_LOAD segments accepted; a RELATIVE relocation outside the segment (or straddling its end) is accepted/dropped; a relocation offset near 2^64 makes `offset+8 <= len` wrap and **panics**; `ApplyBias` accepts a wrapping displacement; PT_LOAD with filesz > memsz == 0 is ignored.
16. **Translate-time model**: `ScanTitle` misses the `REX.W A0-A3 moffs64` absolute-address forms; `ExeBias` accepts a fixed-address executable at or beyond `guest_hi`; `NewManifest/CConfig` passes an unaligned `image_end` (the runtime then refuses the config); `NeedsBase` panics on a hand-built scan with count > 0 and no examples.
17. **Thunks (SPEC 4.2)**: thunkgen accepts float/double/long double/`__int128`/struct-by-value/struct-return/variadic/`va_list`/callback signatures and marshals them as integer-class values; none of the FP, aggregate, variadic or callback classifiers exist yet.
18. **libc HLE**: `calloc` overflow and `malloc(2^62)` return blocks instead of NULL.
19. Observations that are not defects: SDK-built titles can be refused identity mode by a data-word false positive in the scan (documented behaviour); in identity mode pointers outside the arena are raw host pointers by design.
