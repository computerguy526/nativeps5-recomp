## Pipeline cache persistence (static + measured)
Static (mesa/src/kosmickrisp/vulkan/kk_shader.c, kk_physical_device.c): KK serializes MSL SOURCE TEXT (kk_msl_serialize) into the Mesa pipeline-cache blob; `kk_deserialize_shader` re-runs the Metal compile (`kk_compile_compute_pipeline` / `kk_compile_graphics_pipeline`). There is no MTLBinaryArchive. `pdev->vk.disk_cache` is never created, so no Mesa on-disk cache. `kk_physical_device_init_pipeline_cache` only sets pipelineCacheUUID = hash of driver build SHA.
Measured (pipetest/pipetest.c, compute with BDA/int64/int8 + 2-RT blended graphics pipeline, fresh salted shader per row, separate processes):

| Scenario | compute pipeline create | graphics pipeline create |
|---|---|---|
| 1st launch, never-seen shader (cold) | 36.5 / 50.0 / 57.6 / 56.2 ms (4 runs) | 28.6 / 22.6 / 31.2 / 22.6 ms |
| 2nd+ launch, no app cache blob | 0.92, 1.03 ms | 1.14, 1.27 ms |
| 2nd launch with Mesa cache blob loaded | 0.48, 0.55 ms | 1.06, 1.12 ms |
| 2nd launch, MESA_SHADER_CACHE_DISABLE=true, no blob | 1.29, 1.37 ms | 1.79, 1.83 ms |
Checksum of the compute result identical cold vs warm. Persistence therefore comes from Apple's own Metal compiler cache (~/…/C/com.apple.metal/<gpu>/{functions,libraries}.data under $DARWIN_USER_CACHE_DIR), keyed on MSL source, not from KK. Caveats: OS-managed (can be evicted, differs under App Sandbox containers, not shippable/pre-warmable, not covered by the chain stamp). Our own "recorded prewarm list" (SPEC 5.2.3) is still needed to populate it; app-controlled persistence would need Metal 4 archives (Phase B, pipeline-creation path only). Test machine's cache was warm for other apps; only salted shaders were cold, which is what is reported.

## AnyPS5 recompiler / agc_frame_replay on arm64
- Full AnyPS5 build: NOT done. Blockers: (1) CMakeLists.txt forces x86_64 on Apple hosts and has `FATAL_ERROR` at line 849 for non-x86_64; (2) every 3rdparty submodule dir is empty (need SDL2, glslang, SPIRV-Tools/Headers, ffmpeg-core, freetype, libusb, zstd, ...); `ANYPS5_USE_SYSTEM_DEPS=ON` covers only SDL2/freetype/Vulkan-Headers/SPIRV/glslang, while `add_subdirectory(3rdparty/ffmpeg-core)` etc. remain; (3) `agc_frame_replay` links libSceAgcDriver + guest libkernel + libc, which are the x86-64 guest-runtime shims (inline asm/arena/ABI code in ~59 files under core/libs). Smallest path to frame replay: a separate arm64 port of libkernel/libc guest shims (a milestone-sized job), not a tool-target tweak.
- No captured frame exists in the repo (capture dirs are synthesized by test writers only), so frame replay correctness and frame time: NOT MEASURED.
- SUCCEEDED: the shader recompiler (124 translation units from core/shader/recompiler, ./recomp_build.sh) compiles for arm64 with ZERO source changes (clang++ -std=c++20 -arch arm64, brew glslang headers), and AnyPS5's own `agc_shader_replay` tool (tools/ShaderReplay.cpp) links and runs natively (work/s3/agc_shader_replay; link needs only a stub for the cmake-generated ShaderCacheVersion symbols, link_replay.sh). It deserializes the repo's embedded .req fixtures (reqs/, from RequestSerializerTests.cpp) but those are s_endpgm stubs, so no real SPIR-V from them.
- My own driver rdna2spv/rdna2spv.cpp (request template copied from DenormalFlushElimination.cpp) feeds hand-assembled RDNA (v_mul_f32 chains + MUBUF store, 5 to 1603 words) through the recompiler on arm64: spirv-val clean (Vulkan 1.3), uses SignedZeroInfNanPreserve + GroupNonUniform. Recompile time: 5 words 1.64 ms first / 0.24 ms second; 103 w 1.26/1.09; 403 w 5.2/4.5; 1603 w 27.4/23.7 ms.
  Constant-folded SPIR-V is 770 words for all sizes, so this is a recompiler-on-arm64 proof, not a representative shader workload.
- KK compile of that SPIR-V (pipetest/spvrun.c, layout set0/bind0 SSBO + 128 B push): pipeline create 77.6 ms first process, 1.1 ms second. KK produced valid MSL (MESA_KK_DEBUG=msl). Not dispatched with real guest data (BDA/V# ABI needs the driver), so GPU-side correctness of recompiled shaders is NOT verified.
- Smallest next step for real timings: capture .req files from a running x86 AnyPS5 (APS5_DUMP_SHADERS=1 / frame capture), replay with the arm64 agc_shader_replay --spv, run spvrun on the outputs; for frames, port the guest runtime or run the x86-64 AnyPS5 under Rosetta against an x86-64 KK build as the interim differential.

## Arena coexistence (coordinator add-on)
pipetest/arena.c: mach_vm_region confirms 0x7000000000..+0x8C00000000 free, `mach_vm_allocate(..., VM_FLAGS_FIXED)` succeeds (kr=0), then vkCreateInstance + vkCreateDevice on KK, then 6 host-visible allocations mapped and touched (3x256 MB, 3x1 GB). 5 launches (arena.out): all PASS. The reservation stays exactly contiguous (BASE start, full 0x8C00000000 covered; the kernel reports it as 4480 x 128 MB regions, unchanged before and after), and every KK mapping landed outside it (e.g. 0x11e834000, 0x3be924000, 0xb1e02c000, all below 0xc00000000). The reservation is not freed or split by KK. Not tested: KK buffers whose GPU VA (BDA) overlaps the arena (GPU addresses are Metal-assigned, unrelated to the CPU reservation), and importing arena memory via VK_EXT_external_memory_host (extension is present).
