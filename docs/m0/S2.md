## Headline
1. **Fork confirmed for now.** A PS5-SDK-built ELF (clang 23, x86_64-sie-ps5) was lifted, assembled, linked and ran natively (prints `fib=463`, leading digits of fib(24)=46368 as designed). PS4Recomp's own hello_world.elf also runs. Lifter-level unsupported: 0–0.06% on non-AVX2 code, 0.92% on AVX2-heavy Syobon eboot; ~40 AVX2/FMA forms total.
2. **`ps4-recomp analyze` is not a usable census.** It reports 4.98% unsupported on Syobon (28,534); the lifter actually emits 5,265 stubs (0.92%). `lifter.IsOpcodeSupported` is a stale hand list. Count emitted `// UNSUPPORTED:` markers instead.
3. **Three PS5-format loader blockers (L6), all local fixes:**
   - SELF magic 54 14 F5 EE unrecognised (only 4F153D1D).
   - Syobon uses standard dynamic tags (DT_RELA=7, SYMTAB=6, JMPREL=0x17) plus new 0x6100004x SCE tags; loader sees 0 relocations and 0 imports.
   - Payload SDK default `-fno-plt` GOT-style imports abort at first import call (`Unresolved indirect jump/call to 0xc938`). `-fplt` works.
4. **The spec's "interim x28=0" does not exist.** macOS arm64 SIGKILLs (exit 137) any binary with `__PAGEZERO` below 4 GiB (id/pz.c). Guest addresses start at 0 and `MemoryImage` is a dense slice from 0 (113 uses). L2 must move image, allocator, stack and TLS to >=0x70_0000_0000 and bias emitted address constants, as one change.
5. **Flat stack (§3.3) is cheap if the shadow stack pointer lives in a register.** In memory (ctx) up to ~2.5x in call-saturated loops.

## End to end
`-compile` fails at ps4_ajm.c (missing libatrac9.h/minimp3.h submodules); Gnm .mm need gcn-recompiler and spirv-cross. tools/build_manual.sh skips AJM and three Gnm .mm, with 11 zero-returning stubs (bring-up only: no GPU/audio).
- hello_ps4: runs (`main: Hello world! Waiting 2 seconds!`, `main: Done. Infinitely looping...`), killed by timeout. Guest memory at host 0x7000000000 (0x8000000000 bytes).
- ps5_hello_k (`sceKernelWrite` + fib(24), `-fplt`): **runs correctly**.
- Same with `-fno-plt`: aborts at first import call.
- Freestanding raw-syscall program: `Unsupported guest instruction SYSCALL` (lifted only in libkernel-stub shapes).
- ps5 hello_world/stdio/cxx: lift and assemble, not run (unresolved imports; hello_cxx needs C++ EH and threads).

**x28=0 identity variant:** hand-made `mach_vm_allocate` arena at 0x70_0000_0000 works; hand-written identity-addressed flat-stack fib (B1/B3) with guest and shadow stacks inside a 1 GiB arena returns 832040 (bench/arena_test.c). Running lifter output with x28=0 is impossible as-is: guest addresses start at 0 (image vaddr 0, TLS 0x130000, first mmap 0x8150000, stack 0x7ffffefc8) and the low 4 GiB is unmappable. Guest layout, emitted absolute constants (return addresses, `lea rip`, dispatch keys, relocation addends) and a sparse `MemoryImage` must change together.

## Vector temporaries — answer
XMM0-15 = v0-v15, YMM uppers = v16-v31. Scratch vectors hard-coded in v16-v31 (mostly v31), with `vU<n>` placeholders; `fixUpperHalves` (arm64_lifter.go:805) is a regex post-pass that renames colliding scratch and, in YMM-using functions, saves/restores touched uppers with stp/ldp on the host stack. Non-YMM functions use scratch freely (assumes SysV caller-saved). Hole (by reading): no restore emitted if the lowering contains `ret`, `br` or a branch to `L_fn_`. Syobon: ~10,000 spill sequences, 1,282 VZEROUPPER.

## PF/AF/DF coverage (§3.10)
- **PF:** not computed for integer ops; after FP compare kept in V (aliases OF). JP/JNP/SETP/CMOVP test V. LAHF/PUSHFQ store PF=0. PF consumers: hello_ps4 13, Syobon 110 (8 directly after VUCOMIS*; 102 at block start, unverified), hello_cxx 0.
- **AF:** never modelled. BCD 0 everywhere; Syobon 4 PUSHFQ + 2 POPFQ.
- **DF:** CLD nop; STD → unsupported stub (fails loudly). No REP string ops reachable.
- GuestContext flag reconstruction must also carry static carry polarity (`carryPol`/`cfinv`) per fault point.

## Recommendation for §3.1
Fork confirmed. No whole structured IR first. Before L1/L2:
1. Replace ~290 literal `[x28, ...]` sites (simd 97, alu 31, trampoline 16, tso 7, ...) with one `memOperand()` emitter.
2. Move `fixUpperHalves` and the TSO rewriter onto typed operands with explicit vector-scratch allocation (fixes the control-leaves hole).
3. Fix PS5 loader before L2: SELF magic, standard dynamic tags, GOT-style imports, sparse/offset `MemoryImage`.
4. Unsupported instructions become translate-time errors.
5. Flat stack with shadow pointer in a register (B1/B3).
Escalate to a thin typed-ARM64 layer only if step 2 can't be made sound.
